MTO 可信链机器人 · 证据链自维护原型

Machine Trust Optimization — 一个常驻监听器 + 一条不可篡改的哈希链。Agent 负责维护，哈希负责被相信。

原则：尽可能少占用人的注意力，给尽可能多的价值。监听器吞掉 95% 的「一切正常」，只在有人必须动手时出声。
边界：Agent 让证据链可以被维护，但只有不可篡改，让证据链值得被相信。本页的链由浏览器 SHA-256 逐块串联，任何一块被改写都会暴露。

需要人

面板只列出在等你的东西。其余状态不占空间——这是设计，不是缺功能。

证据台账

每一条对外主张 = 一条原子事实。它有类型、引用源、有效期和最近核验时间。状态由监听器维护，不是由人记得去查。

新增一条原子事实

常驻监听器

不定时巡检，等事件发生：证据到期、引用源变更、第三方表述漂移、竞品改了引用源。命中后交给门禁裁决。

每 6 秒一次心跳，按概率命中真实存在的薄弱证据。事件只有在台账里真有对应问题时才会产生——不制造噪音。

事件流

门禁（Policy）

授权边界是安全边界，不是效率问题。门禁决定「什么情况下可以自动动手」。裁决三选一：自动开工单 / 仅记录不动手 / 拒绝并告警。

Mandate（不可变授权凭证）

每一次被许可的动作，都附带一张不可变凭证：谁发起、依据哪条规则、策略版本、作用域、强度、生效时间。证据链完整的样子，不只有「现在是什么」，还有「怎么变成现在这样的」。

可信链

审计日志不能自己写自己。每一块的哈希由前一块决定，改任何一块，后面全部对不上；根哈希可锚定到 Agent 改不了的地方。

区块

审计与交付

交付物从一份 PPT，变成一个持续运行的系统 + 一份审计日志。计价单位从「按项目」变成「有多少条主张处于可信状态」。

审计包包含：证据台账快照、全部事件与门禁裁决、全部 Mandate、完整哈希链与锚点记录。可离线复核。


    

    

      
本页能证明什么 / 不能证明什么

      

        
能证明
链上任何一块被改写、被删除、被重排，校验都会定位到具体块号。

        
能证明
每一次变更都有 Mandate：发起人、规则、策略版本、作用域、时间。

        
不能证明
浏览器 localStorage 本身可被人为清空——所以根哈希必须锚定到 Agent 改不了的地方（时间戳服务、公开账本、第三方存证）。

        
不能证明
引用源的真实性。链只保证「记录没被改」，不保证「记录是对的」。核验仍需人批准。
